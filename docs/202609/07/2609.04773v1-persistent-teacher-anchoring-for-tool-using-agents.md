## 摘要
蒸馏在LLM后训练中很常见，其中在线策略知识蒸馏（OPKD）使用学生生成的轨迹为学生后续的强化学习做准备。在每个状态下，学生匹配教师提供的下一个令牌分布。当轨迹进入教师不会访问的状态时，师生分布差距会累积。在工具使用中，这种差距变得重要，因为学生编写的调用在监督之前执行，其观测结果会塑造后续的前缀。提议者-验证者生成通过让教师在生成过程中决定保留学生提出的哪些文本来解决这种漂移。现有公式管理文本，但未涵盖工具执行。我们提出持久教师锚定（PTA），一种学生诱导但教师承诺的轨迹构建。PTA保留分块级验证并添加回合级承诺，允许调用仅在教师验证整个回合后才到达环境。将验证过的分块视为原子生成单元，我们引入持久前瞻，通过推进未来样本并将未完成的样本在固定验证器下跨学生更新携带，从而填充空闲轨迹容量。在Search-R1风格的检索和DeepEyes风格的感知RL中，在相同的下游RL预算下，PTA在下游RL之前应用，相比OPKD，宏best@4提升2.5和2.8个百分点，而前瞻将吞吐量提高24%。

## Abstract
Distillation is common in LLM post-training, where on-policy knowledge distillation (OPKD) uses student-generated trajectories to prepare the student for downstream RL. At each state, the student matches a next-token distribution supplied by the teacher. As the rollout enters states the teacher would not visit, the teacher-student distribution gap can accumulate. In tool use, this gap becomes consequential because student-written calls execute before supervision and their observations shape later prefixes. Proposer-verifier generation addresses this drift by letting the teacher decide which student-proposed text is retained during generation. Existing formulations govern text but leave tool execution outside their scope. We propose Persistent Teacher Anchoring (PTA), a student-induced but teacher-committed rollout construction. PTA retains chunk-level verification and adds turn-level commitment, allowing a call to reach the environment only after the teacher has verified the entire turn. Treating verified chunks as atomic generation units, we introduce persistent lookahead, which fills idle rollout capacity by advancing future samples and carrying unfinished ones across student updates under the fixed verifier. Across Search-R1-style retrieval and DeepEyes-style perception RL, applying PTA before downstream RL improves macro best@4 by 2.5 and 2.8 points over OPKD under the same downstream RL budget, while lookahead improves throughput by 24%.

## 1. 论文的核心问题与整体含义

大语言模型（LLM）日益成为工具使用型智能体，在推理过程中穿插调用外部工具（如搜索引擎、视觉感知工具）。这带来一个关键训练难题：**在策略知识蒸馏（On-policy Knowledge Distillation, OPKD）中，学生模型自己生成轨迹，教师模型事后提供逐 token 分布作为监督信号。但学生的 rollout 会进入教师不会访问的状态，导致师生分布差距在长轨迹中逐步累积，尤其有害的是——在工具使用场景中，学生写出的工具调用会在教师监督到达之前就已执行，返回的观测结果反过来继续塑造后续前缀，形成“错误先执行、监督后到达”的恶性循环。**

论文的核心主张是：教师不应只作为“事后的监督者”，还应参与**轨迹构建过程本身**，决定哪些学生提议的文本可以进入轨迹、哪些工具调用可以真正到达环境。作者将已有的 proposer-verifier generation 思想从纯文本生成扩展到工具执行领域，提出 **持久教师锚定（Persistent Teacher Anchoring, PTA）** ，作为下游强化学习（RL）之前的蒸馏阶段。

更广义的含义在于：论文揭示了一个此前被忽视的维度——在工具使用场景中，**验证的“粒度层级”至关重要**。仅验证文本分块不够，还需要在回合（turn）层面做“提交/承诺”（commitment）决策，才能安全地管理工具执行。

## 2. 论文提出的方法论

### 2.1 核心思想

PTA 的核心思想可以用一句话概括：**学生提议一切，教师验证一切，只有教师验证通过并整体“提交”的回合才能触发工具执行。**

该机制建立在两个层次上：

- **分块级验证（chunk-level verification）**：学生逐块（chunk）提议文本，教师逐 token 验证。学生 token 落在教师 top-K 集合内则保留，否则被教师的 top-1 token 替换，且从该处丢弃已生成的剩余后缀。
- **回合级承诺（turn-level commitment）**：验证过的分块先进入一个“待定助手回合”（pending assistant turn），该回合不属于已提交轨迹。只有当回合达到助手 EOS 或工具调用闭合标签时，PTA 才将整个回合“提交”并入轨迹。**只有已提交的回合才能被工具运行时解析并执行。**

### 2.2 关键技术创新

1. **消除工具调用的两类失败模式**：
   - 执行先于验证（execution before verification）——由回合级承诺解决；
   - 执行后纠正（correction after execution）——因为工具调用一旦执行，修改其中任何 token 都会导致与返回观测不一致，所以验证必须先于执行完成。

2. **处理环境观测的来源规则**：轨迹中区分三类 token——提示（prompt）、已提交助手回合、环境观测。三者都保留在前缀中供后续生成使用，但**蒸馏损失只施加于已提交的助手位置**。观测 token 不被视为模仿目标（不会被训练去复现环境返回的内容）。

3. **持久前瞻调度（persistent lookahead scheduling）**：观察到教师验证器在整个训练过程中固定不变，而学生每步更新，因此可以将验证过的 rollout 状态跨学生更新持久携带。当同步训练中某些样本提前完成、释放出空闲槽位时，调度器用**未来样本**填充这些槽位，提前推进它们。在更新截止前完成的未来样本被“晋升”（promoted）进当前批次；未完成的则作为“结转”（carryover）样本在更新后继续。结转只发生在原子状态边界（验证过的分块之后或完整环境转换之后），从而保证学生参数更新不会让未经验证的原始内容直接进入轨迹。

### 2.3 数学表达

**验证器映射（Verifier as a map）**：

给定已验证上下文 \( h \)，学生提议 \( \tilde{x} \sim p_\theta(\cdot|h) \)。教师验证器的决策为：

\[
V_\phi(\tilde{x}|h) =
\begin{cases}
\tilde{x} & \tilde{x} \in \mathcal{T}_K(h) \\
x^\star(h) & \text{otherwise}
\end{cases}
\]

其中 \( \mathcal{T}_K(h) \) 为教师的 top-K 支持集，\( x^\star(h) \) 为教师的 top-1 token。

**提交 token 的诱导分布（induced distribution）**：

设 \( r(h) = \sum_{y \notin \mathcal{T}_K(h)} p_\theta(y|h) \) 为学生在教师 top-K 外的概率质量，则实际进入轨迹的 token 服从：

\[
\pi(x|h) =
\begin{cases}
p_\theta(x|h) & x \in \mathcal{T}_K \setminus \{x^\star\} \\
p_\theta(x^\star|h) + r(h) & x = x^\star \\
0 & x \notin \mathcal{T}_K
\end{cases}
\]

等价地表示为混合分布：

\[
\pi(\cdot|h) = (1-r(h))\,\bar{p}_\theta(\cdot|h) + r(h)\,\delta_{x^\star(h)}
\]

其中 \( \bar{p}_\theta \) 为学生分布截断到 top-K 后重新归一化。这一形式精确刻画了 PTA 的混合特性：大部分情况下保留学生自己的提议，只在教师拒绝时替换为教师的 top-1 token。

**与纯学生策略的距离**：两个分布的全变差距离恰为 \( r(h) \)，即被教师拒绝的概率质量。当 \( K \) 趋于全词表时，\( \pi = p_\theta \)（纯在策略）；当 \( K=1 \) 时，\( \pi = \delta_{x^\star} \)（纯离线策略）。PTA 使用 \( K=3 \)，且实测替换率仅 9.5%~11.6%，接近在策略端。

**目标函数**：PTA 仍用前向 KL 散度，但只在已提交助手位置施加：

\[
\mathcal{L}_{\text{PTA}}(\theta) = \frac{1}{N_t} \sum_{b \in \mathcal{B}_t} \sum_{i \in \mathcal{A}(\tau_b)} D_{\text{KL}}(q_{b,i} \| p_{b,i})
\]

其中 \( \mathcal{A}(\tau_b) \) 是轨迹中标记为助手（assistant）源的位置集合。**损失函数本身没变，变的是 rollout 的构建方式和损失施加的位置集合。**

### 2.4 算法流程（文字描述）

PTA rollout 的流程为：初始化已提交轨迹 → 在预算内循环：清空待定回合 → 内层循环中由学生提议分块、教师验证分块、将验证后的分块追加到待定回合，直到回合被终结 → 将整个回合提交入轨迹 → 解析工具调用：若是有效调用则执行并追加观测；若是最终答案则标记为终止。

## 6. 论文的主要结论与发现

1. **PTA 提升下游 RL 的最终策略质量**：在相同下游 RL 预算下，PTA + RL 比 OPKD + RL 的 macro best@4 在检索场景提高 2.5 分、感知场景提高 2.8 分。最显著的单点增益出现在 Musique（多跳检索）和 HRBench8K（更高分辨率感知），这两个恰恰是早期工具交互会深刻影响后续路径的任务。
2. **优势在预对齐阶段就已存在**：在下游 RL 之前，PTA 对齐检查点在全部 6 项感知指标上超过 OPKD，说明蒸馏阶段本身的质量差异是下游差异的重要来源。
3. **工具调用内部的教师替换虽稀有但关键**：工具调用内部替换仅占全部已提交助手 token 的 0.05%（检索）和 0.82%（感知），但抑制这些替换会完全消除 PTA 的对齐优势。安全时机（delayed execution）本身不够，必须配合调用内容层面的修正。
4. **教师锚定的前缀更容易被稀疏蒸馏保真**：在 PTA 的教师提交前缀上，相同 top-N 预算保留更多教师概率质量；OPKD 在最小保留质量上有尖锐下降，说明同一稀疏预算下 OPKD 会丢失更多教师分布信息。
5. **前瞻调度提升吞吐 24%**：通过将未来样本提前到空闲槽位、跨更新结转未完成样本，吞吐从 0.519 提升至 0.644 samples/s，且不改变验证、承诺和执行的语义。
6. **PTA 本质上是“选择性学生轨迹”**：提交 token 的诱导分布距离学生自身策略的 TV 距离恰为教师拒绝率——随着训练推进，拒绝率从 0.127 降至 0.098，学生的轨迹越来越接近自己原本的行为，但保留了教师的关键修正。

## 7. 优点

1. **问题定位精准且具有实际意义**：捕捉到 proposer-verifier generation 在工具场景中的真实缺口——只验证文本不管执行，等于没验证。将验证粒度从 chunk 提升到 turn 的层次化设计清晰自然。
2. **严格的数学刻画**：对提交 token 的诱导分布给出了精确的混合分布公式，证明其与学生策略的 TV 距离恰为拒绝率；K 的取值在在策略和离线策略之间形成插值，理论框架非常优雅。
3. **消融设计“一刀见血”**：仅抑制工具调用内部替换就消除全部优势，同时保留所有其他安全机制，这一消融清楚地证明结果不是由安全时机或观测掩码等伪机制带来的。
4. **诊断实验连接了机制与结果**：通过 top-N 保留质量等分布诊断，解释了 PTA 为什么在稀疏监督下更好，使结论不止停留在基准分数差异。
5. **同策略保真度高但有教师修正**：学生提出 90% 以上内容，训练出的策略不是教师轨迹的模仿者，而是一个“保留了自身风格但被教师关键修正过”的策略，这对后续 RL 探索可能是有利的。
6. **持久前瞻在工程上实用**：不改变验证语义、不打断原子边界，只是填充空闲容量——是一个“免费的午餐”式优化。

## 8. 不足与局限

1. **泛化覆盖有限**：仅覆盖检索和视觉感知两类工具；代码执行、数据库访问、多智能体交互等工具类型完全未涉及。工具调用参数的特征（自然语言 query vs 数值坐标）会影响验证统计表现，因此在不同工具类型上的效果需要单独验证。
2. **单次训练、无训练种子统计**：每设置只训练一次，显著性检验只反映评估采样变异，无法评估训练过程的稳定性。这在实验严谨性上是明显短板。
3. **特意回避了错误恢复能力**：PTA 在训练前阶段就修正了工具调用错误，因此预训练策略从未见过这些错误状态。虽然下游 RL 会恢复无约束的学生驱动 rollout，但论文的评价目标是最终策略质量而非恢复能力，两者可能存在张力——预对齐阶段暴露错误是否反而有助于下游学得更鲁棒的表征，这个问题未被讨论。
4. **教师推理成本未消解**：PTA 需要教师在 rollout 期间进行推理。持久前瞻只是利用闲置容量，不改变模型推理的总成本。在更大的模型规模或更长任务中，验证器成本可能成为瓶颈，论文未做扩展性分析。
5. **超参数空间单点采样**：阈值、chunk size、top-1 确定性替换、全 token 验证——都是单一配置。论文明确说明这些是“替代实例化”而非被研究的变量；不同的验证配置（如随机采样替换、只验证工具调用）可能得到不同结论。
6. **统计功效不均**：NQ、HotpotQA、VStar 上的差异没有达到统计显著，VStar 仅有 191 个评测问题。宣称的优势主要来自少数几个大数据集上的显著差异。
7. **报告信息缺口**：未披露 GPU 型号和总训练耗时，复现成本难以估计；感知场景中奖励依赖 Gemini 作为 judge，这种自动评估本身有引入偏差的可能。
