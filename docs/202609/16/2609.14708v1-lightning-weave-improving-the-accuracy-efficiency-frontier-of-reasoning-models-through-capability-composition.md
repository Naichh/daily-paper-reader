## 摘要
高效推理的一个核心目标是改进准确率-效率前沿。然而，同时提升推理准确率和推理效率可能颇具挑战，因为这两个目标可能偏好不同的推理行为。经过独立后训练的模型已在准确率和效率上展现出各自的优势。我们提出 Lightning Weave，这是一种后训练框架，通过同策略蒸馏在单个学生模型中提取并组合这些独立习得的能力。每种习得的能力由模型在后训练前到所得专家模型之间的策略偏移来表示。Lightning Weave 在共享的学生 token 状态处组合对齐后的对数比值偏移，并使用 Tilted-Target DOPD 将缓存信号转换为稳定的学习目标。每个锚点对会对缓存的轨迹评分一次，从而使后续学生模型训练无需同时服务多个在线锚点模型。在多种学生模型以及数学和代码基准上，Lightning Weave 相较基础学生模型有显著提升，并达到了当前最优的准确率-效率前沿。在 Qwen3.5-4B 上，它将 HMMT 2025 准确率从 59.2% 提升至 64.0%，同时响应 token 数减少 10.7%；并将 LiveCodeBench v5 准确率从 41.7% 提升至 54.2%，同时响应 token 数减少 9.6%。调整锚点信号的相对强度，可在经验上形成很强的准确率-效率帕累托前沿。这些结果确立了 Lightning Weave 是通过能力组合实现高效推理的一条新的实用路径。代码即将发布。

## Abstract
A core goal of efficient reasoning is to improve the accuracy-efficiency frontier. However, jointly improving reasoning accuracy and inference efficiency can be challenging, as the two objectives can favor different reasoning behaviors. Independently post-trained models already offer distinct strengths in accuracy and efficiency. We introduce Lightning Weave, a post-training framework that extracts and composes these independently learned capabilities in a single student through on-policy distillation. Each acquired capability is represented by the policy shift from the model before post-training to the resulting specialist. Lightning Weave combines aligned log-ratio shifts at shared student token states and uses Tilted-Target DOPD to convert the cached signals into a stable learning target. Each anchor pair scores the cached trajectories once, enabling subsequent student training without serving multiple live anchor models concurrently. Across diverse student models and benchmarks in mathematics and code, Lightning Weave substantially improves upon the base students and achieves a state-of-the-art accuracy-efficiency frontier. On Qwen3.5-4B, it raises HMMT 2025 accuracy from 59.2% to 64.0% with 10.7% fewer response tokens, and LiveCodeBench v5 accuracy from 41.7% to 54.2% with 9.6% fewer response tokens. Adjusting the relative strengths of the anchor signals yields a strong empirical accuracy-efficiency Pareto frontier. These results establish Lightning Weave as a new practical route to efficient reasoning through capability composition. Code will be released soon.

# Lightning Weave 论文深度总结

## 1. 核心问题与研究动机

- **背景**：大型推理模型在复杂任务上表现优异，但生成长推理链带来高昂推理成本；激进截断推理链又会损害准确率。
- **核心矛盾**：高效推理的目标是改进"准确率–效率前沿"，但准确率与效率两个目标往往偏好**不同的推理行为**，联合优化时一方提升常以另一方为代价。
- **关键观察**：现实中已存在大量**独立后训练**的专家模型——准确率导向的（如 Klear）与效率导向的（如 DECS）——它们各自已经学会互补的能力。
- **核心研究问题**：能否将这些独立后训练习得的能力**提取并组合**到单一学生模型中，从而同时改善其准确率与效率前沿？
- **整体含义**：论文将"能力组合"确立为高效推理的一条新实用路线，区别于从零联合优化、参数空间模型合并、或多教师在线蒸馏等既有思路。

## 2. 方法论

### 2.1 核心思想

- 用**策略偏移（policy shift）**而非端点策略来表示每种能力：将某专家与其**后训练前的检查点**配对，构成**锚点对（anchor pair）** $(π^+, π^-)$。
- 该偏移 $r_\Delta(a|s) = \log \frac{π^+(a|s)}{π^-(a|s)}$ 刻画后训练带来的行为改变，而非专家模型的绝对分布。
- 在**共享的学生 token 状态**上对齐多个锚点对的偏移，将其组合为一个联合学习目标，转移给单一学生模型。

### 2.2 关键技术细节

- **DOPD 基础**：理想化的序列级目标为最大化 $\mathbb{E}_{\hat y\sim π_θ}[\Delta(\hat y|x)] - α D_{KL}(π_θ \| π_b)$，其中 $π_b$ 为初始学生（行为策略）。
- **离线缓存的困境**：在线 DOPD 需同时服务 $2K$ 个锚点模型，成本高昂。若简单缓存行为策略 $π_b$ 采样的轨迹并用其采样 token 的 KL 估计量（naive offline），当学生偏离 $π_b$ 后，缓存的代理目标不再等于真实 KL 正则项，**在目标处梯度不消失**，训练会被持续推离目标（附录 A.2 给出具体反例）。
- **Tilted-Target DOPD（单锚点修正）**：将缓存偏移显式"倾斜"为明确的目标分布
  $q(a|s) = \frac{π_b(a|s)\exp(r_\Delta(a|s)/α)}{Z(s)}$，
  并以 $L_{TT}(θ)=α\,\mathbb{E}_{s\sim d_{π_b}}[D_{KL}(π_θ(\cdot|s)\|q(\cdot|s))]$ 为损失。该目标与原 KL 正则化 DOPD 目标等价（相差 θ 无关常数），且**在 $π_θ=q$ 处损失与梯度同时为零**，给出良定义的稳定不动点。
- **多锚点组合（Lightning Weave）**：对 $K$ 个锚点对做加权对数比值组合
  $r_w = \sum_i w_i r_i$，再构造联合倾斜目标
  $q_w(a|s) = \frac{π_b(a|s)}{Z_w(s)}\prod_i\left(\frac{π^+_i(a|s)}{π^-_i(a|s)}\right)^{w_i/α}$。
  这是**围绕共享学生先验的相对策略变化之积**，而非教师分布的算术混合：一致的改动相互强化，冲突的改动在局部按权重调和。
- **效率优势**：每个锚点对只需对缓存轨迹评分一次，之后训练只服务学生模型，不再需要并发服务在线锚点；调整权重 $w_i$ 即可得到不同的准确率–效率权衡点。
- **工程细节**：跨 tokenizer 时通过字节级前缀投影对齐（仅保留原子映射且前后锚点共享同一文本前缀的位置）；实现上用 16 个候选 token 加一个残差"other"的有限候选目标，配合平方对数残差代理损失，保持零损失/零梯度不动点性质。

## 3. 实验设计

- **学生模型（5 个）**：Qwen3-1.7B、Qwen3-4B、Qwen3-4B-Thinking-2507、Qwen3.5-4B、OLMo-3-7B-Think，跨模型规模与家族。
- **锚点对**：准确率导向 Klear（Qwen3-8B-Base → Klear-Reasoner-8B）、MiMo-RL（MiMo-7B-Base → MiMo-7B-RL-0530）；效率导向 DECS（DeepSeek-R1-Distill-Qwen-1.5B → DECS-1.5B）。
- **训练数据**：数学从 Skywork-OR1-RL-Data 取 3,200 条 prompt；代码从 KlearReasoner-CodeSub-15K 取 3,200 条（过滤长度、去重，并筛查与 LCB v6 无重叠）。
- **Benchmark**：数学 AIME 2024、AIME 2025、HMMT February 2025（各 30 题，64 采样）；代码 LiveCodeBench v5（279 题）、v6（131 题），Avg@4。
- **对比方法**：
  - 基础学生模型、Klear-only、DECS-only、MiMo-RL 单锚点；
  - 外部高效推理基线：SimpleSD、Qwen3-4B-Thinking-2507-Art、PromptCoT 2.0、模型插值 MI；
  - 消融对照：Online DOPD、Naive Offline、Data Mixture、两种顺序的 Sequential Composition。
- **评价指标**：准确率、平均响应 token 数，以及 AES（Accuracy–Efficiency Score，相对各自基座逐基准计算后取均值，对准确率损失惩罚更重）。

## 4. 资源与算力

- 论文**明确报告了算力开销**：所有 GPU 阶段使用**单节点 8 张 H100**，bfloat16 精度；Qwen 用 Megatron-Core 训练，OLMo 用 PyTorch FSDP。
- 训练配置：回放 12,800 条缓存轨迹 2 个 epoch，100 轮 × 256 条轨迹，每轮 4 次优化更新（共 400 次更新），全局 batch size 64，学习率 $1\times10^{-6}$ 恒定，Adam，α=2.0。
- 成本对比（附录表 6）：四种 Qwen3 设置下，Lightning Weave 相比 Online DOPD 降低 **1.70–2.18×** GPU 小时；三锚点 Qwen3-4B 外推五组组合时，摊薄成本降低约 **4.58×**（21.47 vs 98.30 GPU 小时）。

## 5. 实验数量与充分性

- **规模**：主表覆盖 5 个学生模型 × 5 个 benchmark；另有 Qwen3-4B-Thinking-2507 与 Qwen3-4B 两组 5 点权重扫描、3 种锚点组合的泛化实验（并扩展到 Qwen3-1.7B 与 Qwen3.5-4B）、两组消融（倾斜目标修正、多锚点组合方式）、2 个定性案例研究。
- **充分性**：
  - 跨模型规模（1.7B–7B）、跨模型家族、跨数学/代码双领域验证，泛化性证据较充分；
  - 消融设计**匹配了学生初始化、prompt 序列、轨迹预算与更新预算**，对照公平；
  - 权重扫描展示了连续可控的帕累托前沿，而非单点结果；
  - 所有方法在相同题目集上评测，代码评测使用官方抽取与测试执行。
- **客观性/公平性上的保留**：每个配置**只训练一次**（seed 1234），论文指出重复生成只衡量解码方差而非训练种子方差，因此缺少训练稳定性/方差的统计证据；部分 LCB 结果在不同表格中使用了 Pass@1 与 Avg@4 两种口径，需注意跨表比较。

## 6. 主要结论与发现

- 能力组合在**所有 5 个学生模型上均取得最高 AES**，一致优于基座与任一单锚点策略。
- 代表性提升：Qwen3-4B 平均准确率 +4.02 分、响应 token −19.7%；Qwen3-4B-Thinking-2507 平均准确率 +4.5 分、token −9.0%；Qwen3.5-4B 平均准确率 +9.70 分、token −5.3%，其中 HMMT 2025 从 59.2%→64.0%（token −10.7%），LCB v5 从 41.7%→54.2%（token −9.6%）；OLMo-3-7B-Think 平均准确率 +3.74 分、token −12.9%。
- 调节锚点权重可得到一族学生策略，其非支配点构成**经验帕累托前沿**，且在各 token 预算下（含紧预算）均优于单锚点。
- 多锚点可扩展：三锚点（Klear+DECS+MiMo-RL）取得最高 AES 0.42；加入某能力锚点会使工作点朝该能力方向移动，行为可预测、可控制。
- 消融表明：Tilted-Target 与 Online DOPD 性能相当但训练管线更易实现，且显著优于 Naive Offline；相较 Data Mixture 与 Sequential Composition，Lightning Weave 避免了数据稀释与顺序偏置。
- 定性案例显示组合确实保留了各锚点的互补行为（如 MiMo-RL 与 Klear 各解决对方失败的一题）。

## 7. 优点

- **问题视角新颖**：不做从零的联合优化，而是"回收"已独立后训练好的专家能力，绕开准确率与效率目标的行为冲突。
- **表示方式巧妙**：用锚点对的对数比值（策略偏移）表示能力，天然与参数空间解耦，无需模型参数兼容性，也便于跨 tokenizer 对齐。
- **理论上有保证**：Tilted-Target DOPD 给出了显式目标与严格不动点（损失与梯度在目标处归零），并证明与 KL 正则化 DOPD 目标等价、组合目标的唯一性与排列/基线/尺度不变性，弥补了朴素离线缓存的缺陷。
- **工程高效**：锚点只评分一次、缓存复用、训练时只服务学生，显著降低 GPU 成本并支持权重扫描的摊薄复用。
- **可控性强**：权重连续可调，产生显式帕累托前沿，并支持多锚点扩展，实用性好。

## 8. 不足与局限

- **模型规模受限**：受算力限制，实验仅覆盖 10B 以下模型，更大规模是否仍成立未知。
- **依赖匹配锚点对**：方法要求同时拥有目标能力的后训练模型**及其对应的预锚点**；对新任务或缺失预锚点的场景难以适用。
- **效率增益有限**：虽然兼顾了准确率，但纯效率导向方法的 token 压缩幅度更大，Lightning Weave 的效率提升相对温和。
- **离线近似的边界**：倾斜目标建立在缓存状态分布 $d_{π_b}$ 上，学生大幅偏离后缓存状态覆盖不足；有限候选（top-16 + 残差）与跨 tokenizer 掩码也引入了实现层近似（论文中约 93.8–100% 位置有效）。
- **实验统计性偏弱**：每个配置仅训练一次、无训练种子方差报告；部分指标口径（Pass@1 vs Avg@4）在不同表格间不完全一致，跨表比较需谨慎。
- **评测范围**：集中于数学与竞赛代码，尚未覆盖智能体推理、工具使用等更广泛场景（作者亦将其列为未来工作）。
