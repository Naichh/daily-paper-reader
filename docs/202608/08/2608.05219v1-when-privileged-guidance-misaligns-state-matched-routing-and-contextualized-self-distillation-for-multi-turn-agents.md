## 摘要
特权在线策略蒸馏通过允许同步教师利用仅训练可用的参考（如成功轨迹）在每个回合重新评分学生的响应，为多轮智能体提供密集监督。然而，在交互式环境中，学生先前的行动会不断改变执行状态。由于学生采取不同行动或以不同顺序完成子目标，其轨迹可能到达参考未覆盖的状态，从而使参考对实际到达状态的指导变得不可靠。因此，不加区分地应用特权蒸馏会造成状态-参考错配。这一错配引出了一个核心目标：提供与学生当前执行状态兼容的特权参考指导。我们引入了状态匹配路由与情境化自蒸馏（SMRC-SD），它明确决定特权轨迹应在何时以及如何引导在线策略学生。在每一回合，SMRC-SD 验证学生的当前执行状态是否与参考轨迹上的支持状态匹配。蒸馏仅在匹配状态应用，过滤掉参考缺乏局部兼容指导的回合。对于每个匹配状态，SMRC-SD 进一步从成功轨迹构建状态条件下的教师上下文，将监督基于实际到达的状态。在 ALFWorld 和 WebShop 上，SMRC-SD 始终优于无条件的成功全路径蒸馏。使用 Qwen3-1.7B，它在 ALFWorld 上任务成功率从 0.746 提升到 0.865，在 WebShop 上从 0.574 提升到 0.693。受控路由和上下文消融实验支持选择局部支持的回合和构建状态兼容的教师上下文都是这些增益的贡献因素。代码可在 https://github.com/liujunzhuo/SMRC-SD 获取。

## Abstract
Privileged on-policy distillation provides dense supervision for multi-turn agents by allowing a synchronized teacher to re-score the student's response at every turn with access to training-only references, such as successful trajectories. In interactive environments, however, the student's preceding actions continually change the execution state. As the student takes different actions or completes subgoals in a different order, its rollout may reach states not covered by the reference, making the reference an unreliable source of guidance for the state actually reached. Applying privileged distillation indiscriminately therefore creates state--reference mismatch. This mismatch motivates a central objective: providing privileged reference guidance that remains compatible with the student's current execution state. We introduce State-Matched Routing and Contextualized Self-Distillation (SMRC-SD), which explicitly determines when and how a privileged trajectory should guide an on-policy student. At each turn, SMRC-SD verifies whether the student's current execution state matches a supported state along the reference trajectory. Distillation is applied only at matched states, filtering out turns for which the reference lacks locally compatible guidance. For each matched state, SMRC-SD further constructs state-conditioned teacher context from the successful trajectory, grounding supervision in the state actually reached. Across ALFWorld and WebShop, SMRC-SD consistently outperforms unconditional successful full-path distillation. With Qwen3-1.7B, it improves task success from $0.746$ to $0.865$ on ALFWorld and from $0.574$ to $0.693$ on WebShop. Controlled routing and context ablations support both selecting locally supported turns and constructing state-compatible teacher context as contributors to these gains. Code is available at https://github.com/liujunzhuo/SMRC-SD.

## 论文详细中文总结

### 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：在多轮交互式智能体训练中，特权在线策略蒸馏（Privileged On-Policy Distillation, OPD）利用同步教师模型在每一回合重新评分学生的响应，从而提供比稀疏结果奖励更密集的监督信号。这类方法通常将**训练时才能获得的成功参考轨迹**作为特权信息注入教师上下文。
- **关键矛盾**：在交互环境中，学生采取的行动会持续改变执行状态（位置、库存、页面、子目标进度等）。学生可能与参考轨迹采取不同行动或以不同顺序完成子目标，导致其 rollout 到达参考轨迹未覆盖的状态。此时，**参考轨迹虽然对任务整体仍然正确，但可能不包含从当前实际到达状态出发的可用延续**，即产生"状态-参考不匹配"（State–Reference Mismatch）。
- **不加区分的危害**：如果无条件地将完整成功轨迹注入教师上下文（FullPath-SD），教师在对学生响应重新评分时会被与当前状态不兼容的参考所干扰，可能压低合适动作（如"返回搜索页"这类恢复性动作）的概率，从而损害训练。
- **整体含义**：可执行的参考轨迹应当被视为**条件性计划**（conditional plan），其局部合法性必须在用于监督之前经过验证。论文据此提出一个核心目标：提供与学生当前执行状态兼容的特权参考指导。

### 2. 方法论：SMRC-SD

#### 2.1 核心思想
- 将成功轨迹视为**按状态索引的训练资源**。每一回合，先检查学生当前执行状态是否与参考轨迹中的某个支持状态匹配：
  - **匹配**：该回合施加参考条件驱动的自蒸馏信号（SDL），并从参考轨迹中定位匹配位置，构建状态条件化教师上下文。
  - **不匹配**：该回合不施加蒸馏信号，仅由 GRPO 目标优化（GRPO 仍对所有轨迹生效）。
- 两个耦合阶段：**状态匹配路由**（决定是否蒸馏与在何处蒸馏）与**情境化自蒸馏**（决定教师看到什么特权上下文）。

#### 2.2 关键技术细节

1. **状态签名重建**（Reconstructing State Signatures）：
   - 通过环境适配器（adapter）构造紧凑的参考签名与学生签名：参考端由任务元数据和动作前缀 `ā_g,<k` 推导，学生端由实际历史、观测和可行动作集推导。
   - 签名是手工设计的、环境特定的，但共享统一接口：确定性重建、方向性支持关系、动作接地、上下文渲染。

2. **结构化状态匹配与路由**：
   - 动作接地：`˜a_t,k = Γ_g(ā_g,k; A_t)`，验证参考动作在当前可行动作集中可执行。
   - 支持关系：`σ_t |=_g σ̄_g,k` 为方向性判断——学生当前状态满足参考位置 k 的任务要求。该关系允许额外的兼容进度，但对会影响下一动作语义/可执行性的字段做精确检查，不是通用状态相似度。
   - 综合条件：`C_t(k) = I[σ_t |=_g σ̄_g,k] · I[˜a_t,k ≠ ∅]`，加上同任务检索，同时强制任务身份、状态兼容性和候选可执行性。
   - 路由决策：选择最靠后的匹配位置 `k_t = max{k : C_t(k)=1}`，以跳过已完成的子目标；存在匹配时 `w_t = 1`，否则 `w_t = 0`。

3. **情境化教师上下文构造**：
   - 匹配回合的上下文为：`c_SMRC = Render(p_g, Summary(σ_t), ã_t,k_t)`，即完整成功路径 + 当前状态摘要 + 接地候选动作。
   - 完整路径提供全局结构，状态摘要定位已到达的进度，接地候选指明本地延续。教师仍对学生采样的响应打分，不生成替换动作。

4. **与在线学习的集成**：
   - 总体损失：`L = L_GRPO + λ_SDL · L_SMRC_SDL`，其中 `L_SMRC_SDL` 仅对匹配回合计算，分母为所有回合的原始响应 token 数，因此路由减少的是蒸馏总量而非局部权重。
   - 推理时完全移除特权组件，部署策略只使用普通提示。

### 6. 主要结论与发现

- **SMRC-SD 持续优于无条件 FullPath-SD**：
  - Qwen3-1.7B：ALFWorld Average@4 0.746→0.865，Pass@4 0.836→0.914；WebShop Score 0.694→0.825，Acc 0.574→0.693。
  - Qwen2.5-3B：ALFWorld Average@4 0.766→0.883，Pass@4 0.852→0.938；WebShop Score 0.842→0.863，Acc 0.734→0.736。同时超过 SDAR 报告的 0.844。
- **路由是主导贡献，上下文构造提供附加增益**：固定教师上下文为完整路径时，匹配路由将 0.746→0.836；在匹配路由基础上加上 SMRC 完整上下文进一步到 0.865。Dynamic Context（不匹配回合仍用完整路径）仅 0.695，说明不匹配回合的蒸馏确实有害。
- **收益来自轮次身份而非稀疏性**：随机同数量回合选择仅 0.723，远低于匹配回合选择的 0.836；对全部不匹配回合施加 FullPath-SD 也只有 0.750。
- **固定状态干预证实了错配机制**：同样的 FullPath-SD 干预在匹配回合提高观测动作得分，在不匹配回合降低得分（A–C 对比 +0.070）；在匹配且分歧的回合，SMRC-SD 的候选偏好转移幅度（+1.424）显著高于匹配 FullPath-SD（+1.158）和抽象技能（+0.153），证明不是通用任务文本在起作用。
- **结构化状态匹配优于历史匹配**：覆盖从 15.4% 提升到 20.2%，保留 98.8% 历史匹配的同时额外发现 1,775 个历史匹配遗漏的回合，最终策略 0.756→0.865；重放审计中结构化状态 781/781 全部能重新接回成功延续，历史匹配有 8 例因观测相似但状态不同而失败。
- **SMRC-SD 产生更短、更少重复的响应**：最终检查点平均响应长度 78.8 tokens（接近 GRPO 的 79.5，远低于 FullPath-SD 的 142.6 和 Skill-SD 的 255.6），重复 4-gram 率 8.8% 也远低于后两者。

### 7. 优点

- **问题识别精准**：清晰刻画了"状态–参考不匹配"这一上游可靠性问题，将参考轨迹重新定义为条件性计划，具有较强概念价值。
- **方法设计解耦**：将"是否蒸馏"与"如何构造蒸馏上下文"解耦为两个可单独验证的机制，便于消融归因。
- **机制验证充分**：固定状态教师干预直接在不变 rollout 上操纵教师上下文，是验证因果机制的高质量实验设计。
- **控制变量严谨**：同数量随机选择控制、历史匹配器比较、候选+后缀重放审计等，有效排除了多种替代解释（稀疏性、历史相似度、通用任务文本、仅候选可执行但后续不可行等）。
- **部署友好**：所有特权组件仅训练时使用，推理时零额外 token 与零组件开销；CPU 匹配开销很小。
- **表述诚实**：对匹配/不匹配标签的操作性定义、审计的采样性质、固定锚点干预的局限均有明确说明。

### 8. 不足与局限

- **依赖人工环境适配器**：状态签名、支持关系、接地规则均为手工设计且环境特定，虽然接口统一，但迁移到新环境需要重新设计适配器，泛化成本较高；方法声称"无学习/无语义匹配"，但手工程度本身就是一种规模化的局限。
- **单一参考轨迹**：每个训练任务只检索一条成功参考，未探索多条参考或自适应选择参考的机制；对参考缺失或参考本身次优的情形未作处理。
- **无多次种子统计**：固定种子为 0，主结果和消融均为单次运行，没有报告均值±方差，无法评估训练随机性对结论稳健性的影响。
- **评估规模有限**：每个数据集固定 128 个测试任务，虽然任务族覆盖较广，但统计功效有限；WebShop 的 500 个验证 goal 仅用于固定验证集划分，未见更大的测试评估。
- **匹配器只是操作标签**：匹配/不匹配不等于动作对错；论文自己也承认"不匹配"包含等价替代动作或不同实例的情形，无法覆盖所有有效状态。
- **基线可比性瑕疵**：Qwen2.5 下 GRPO、Skill-SD、SDAR 数值来自 SDAR 论文，而 FullPath-SD 与 SMRC-SD 为本地运行，两者协议可能存在细微差异（如 horizon、rollout 数），跨论文对比的公平性不完全保证。
- **训练效率未全面报告**：缺少训练时长、更新耗时、GPU 利用率等指标；CPU 计时审计只覆盖 ALFWorld。
