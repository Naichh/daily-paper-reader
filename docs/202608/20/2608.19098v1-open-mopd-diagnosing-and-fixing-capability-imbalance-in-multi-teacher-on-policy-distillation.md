## 摘要
多教师在线策略蒸馏（M-OPD）作为一种有前景的范式，通过密集的、token级别的奖励监督，将领域专用的强化学习（RL）专家整合为单一的全能学生模型。尽管其在实际中取得了成功，但控制多教师能力整合的优化动态仍然知之甚少，而且明显缺乏开放、严格可复现的配方。在这项工作中，我们在SmolLM3-3B-Base上建立了一个带有oracle路由的受控M-OPD基准，将能力整合与路由模糊性分离开来。我们的调查揭示了显著的能力整合差距：标准M-OPD相对于领域路由的oracle集成仅能捕获35.6%的可用提升空间，而诸如指令跟随等简洁任务则遭受严重退化并过早停滞。关键在于，我们证明了这种失败并非源于梯度冲突，而是源于token级优化预算的严重错配。这一病态由三个正交因素驱动：跨领域的结构性序列长度差异、非均匀学习率导致的动态收敛漂移，以及异步策略更新带来的多步奖励陈旧性。为了解决这些不平衡，我们引入了Open-MOPD，这是一个原则性框架，包含token份额平衡、感知差距的动态预算分配以及学生奖励刷新。这些机制共同系统地恢复了跨领域平衡，将单个可部署学生的提升空间恢复率从35.6%提高到83.4%。我们完全开源了端到端的后训练配方、训练轨迹和评估套件，且所需硬件预算符合学术界的可及性。

## Abstract
Multi-teacher on-policy distillation (M-OPD) has emerged as a promising paradigm for consolidating domain-specialized reinforcement learning (RL) experts into a single generalist student via dense, token-level reward supervision. Despite its practical success, the optimization dynamics governing multi-teacher capability integration remain poorly understood, and open, rigorously reproducible recipes are conspicuously lacking. In this work, we establish a controlled M-OPD benchmark on SmolLM3-3B-Base with oracle routing, isolating capability integration from routing ambiguity. Our investigation reveals a pronounced capability integration gap: standard M-OPD captures only 35.6% of the available headroom relative to a domain-routed oracle ensemble, with concise tasks such as instruction following suffering severe degradation and premature stagnation. Crucially, we show that this failure stems not from gradient conflict, but from a severe misallocation of the token-level optimization budget. This pathology is driven by three orthogonal factors: structural sequence-length disparities across domains, dynamic convergence drift due to non-uniform learning rates, and multi-step reward staleness from asynchronous policy updates. To resolve these imbalances, we introduce Open-MOPD, a principled framework incorporating token-share balancing, gap-aware dynamic budget allocation, and student reward refresh. Together, these mechanisms systematically restore cross-domain balance, elevating headroom recovery from 35.6% to 83.4% in a single deployable student. We fully open-source our end-to-end post-training recipe, training trajectories, and evaluation suites on an academically accessible hardware budget.

## 1. 论文的核心问题与整体含义

- **研究背景**：强化学习（RL）已成为 LLM 后训练的核心范式，能够培养领域专用模型。然而在实际部署中，服务多个领域专用模型的计算成本过高，存在将多个领域专家整合为一个统一学生模型的现实需求。
- **研究范式**：多教师在线策略蒸馏（M-OPD）通过将每个输入 prompt 路由到对应领域专家，提供逐 token 的密集奖励监督，将多个领域能力写入同一学生模型。该范式已在工业界（如 DeepSeek-V4、Kimi K3）得到应用。
- **核心问题**：尽管 M-OPD 在实际中成功应用，但其**优化动力学机制尚不明确**，且缺乏开放、可复现的研究配方。论文在受控条件下（oracle 路由、单一基础模型）发现存在显著的**能力整合缺口**：标准 M-OPD 仅恢复 35.6% 的性能头寸，而简洁的指令跟随（IF）任务相比数学退化了 3.3 倍，且最早出现停滞。
- **关键诊断**：**整合失败的根源并非 token 级教师冲突（梯度冲突），而是 token 级优化预算的严重错配**。论文将这一病理分解为三个独立的因素：跨域序列长度差异、跨域收敛速率差异、以及共享 rollout 重复 minibatch 导致的奖励陈旧性。

## 2. 方法论：Open-MOPD 框架

论文提出三个机制，分别对应诊断中的三个失衡来源，且只改动优化预算的分配方式和奖励计算方式，不改变教师路由和 on-policy 蒸馏目标本身。

### 2.1 Token 份额平衡（Token-Share Balancing）

- **目标**：将梯度 token 预算按领域固定为目标份额 g⋆d，而非由序列长度自然决定。
- **核心思路**：在每批中计算各领域实际 token 占比 stok_d，通过损失权重 w_share_d 进行补偿：
  `w_share_d = g⋆d / stok_d`
- **效果**：应用后加权 token 份额精确等于目标 1/3（每个领域）。在原始 token 份额（math 49.7%、code 49.3%、IF 仅 0.99%）下，IF 的每个 token 被放大约 48 倍，以弥补其约 25 倍的序列长度劣势。
- **设计保留**：不改变 prompt 采样频率和单 token 奖励幅值，因为奖励幅值本身携带关于学生-教师差距的信息。

### 2.2 差距感知的动态预算分配（Gap-Following Allocation）

- **目标**：让优化预算动态跟随跨域教师-学生差距的变化，避免预算被浪费在已收敛领域。
- **核心公式**：
  `w̃_d = w_share_d · Clamp((m_d / m_ref)^α, 0.05, 20)`
  其中 m_d 为领域 d 的每 token 平均奖励幅值（EMA），m_ref 为当前 batch 中所有领域的 m_d 均值，α = 1。
- **直觉**：m_d 是剩余蒸馏差距的可观测代理。差距大的领域获得更多预算，已收敛领域自然减少预算。
- **关键实验发现**：反向归一化（α = -0.5，即给已收敛领域更多预算）会形成正反馈回路，导致训练在 step 74 崩溃。

### 2.3 学生奖励刷新（Reward Refresh）

- **目标**：解决多步内更新（K > 1）中学生策略漂移导致的奖励过时问题。
- **核心思路**：在每次内更新前，用**当前学生**的 log-probabilities 重新计算学生相关奖励项，同时**复用缓存的教师 log-probabilities**（教师每个 rollout batch 只需一次 prefill）。
- **公式**：
  `δ_t^(k)(v) = sg[log π_φ_d(x)(v|x, y<t) − log π_θ^(k)(v|x, y<t)]`
- **实现成本**：复用 PPO 已有的 actor forward，无需额外学生 forward。实测中密集奖励计算仅占单步的 2.2%，奖励刷新带来的额外耗时在噪声范围内可忽略。

### 2.4 完整流程（三阶段配方）

1. **Stage I**：混合域 SFT —— 从 SmolLM3-3B-Base 出发，在 math/code/IF 三域数据上训练 4 个 epoch，得到共享初始点 πmixsft；
2. **Stage II**：构建领域 RL 教师 —— 每个领域从 πmixsft 独立初始化，仅在自己的可验证奖励上做 GRPO 训练，得到三个专家 π_φ_math、π_φ_code、π_φ_IF；
3. **Stage III**：多教师 on-policy 蒸馏 —— 学生同样从 πmixsft 初始化，领域标签硬路由选择对应教师，使用带三个机制的改进目标训练。

## 6. 主要结论与发现

1. **整合缺口是真实且不对称的**：Naive M-OPD（28.05）比 RouteOPD（31.55）低 3.50 分；IF 领域缺口 6.16 分，是数学（1.89）的 3.3 倍，且是最早停止改进的领域。
2. **教师冲突不是主导瓶颈**：平均 token 冲突仅 0.126 nat（远低于 1 nat 冲突阈值），高冲突 token 占比平均仅 0.62%；移除或替换高冲突 token 均损害性能（最高 −0.83 分）。
3. **优化预算错配是根源**：三大因素——结构序列长度差异（IF 约 409 token vs math/code 约 10,500 token）、收敛速率差异（m̄ 收缩速率 IF 2.4× vs math 2.1× vs code 1.9×，导致即使 token 份额均等，预算份额也会在 25 步内从 48.7% 跌至约 9%）、奖励陈旧性（K=32 时 rollout-to-current KL 达 0.216，PPO 裁剪 token 占比 86%）。
4. **Open-MOPD 有效修复整合缺口**：总恢复率从 35.6% 提升至 83.4%（总分 31.24），距离 RouteRL 仅差 1.11 分；IF 恢复效果显著（43.64 → 49.58）。

## 7. 优点

- **受控基准设计的严谨性**：使用 oracle 路由（基于真实域标签）将"路由错误"从"能力整合"中分离，精确隔离了研究对象；RouteOPD 作为"部署期整合缺口"的参考设计合理。
- **诊断的严谨性与排除法**：先系统排除教师冲突假设（三路独立证据），再定位到预算错配，论证路径清晰完整。
- **机制与诊断一一对应**：三个机制分别对应三个测量的失衡源，消融实验可独立验证每个机制的因果贡献。
- **公式设计的洞察**：指出"反向归一化"（给低奖励领域更多权重）的错误直觉会形成正反馈崩溃回路，并给出实证（step 74 collapse），验证了符号方向的结构性意义。
- **开源与可复现性承诺**：完整开放三阶段配方、checkpoints、训练轨迹与评估套件，且以学术界可负担的 8×A100-80GB 为约束条件。
- **计算效率设计巧妙**：reward refresh 复用 PPO 已有的 actor forward，教师状态全程缓存一次 prefill，实测开销在噪声范围内。

## 8. 不足与局限

- **领域覆盖有限**：仅三个领域（数学、代码、指令跟随），未涵盖更广泛的通用能力场景；用户真实场景可能存在更多且相互关联的领域。
- **规模外推风险**：实验在 3B 参数规模上进行，性能动态、教师-学生差距行为、预算失衡强度在 7B/70B 规模下的外推性未验证；论文引用的工业案例（如 DeepSeek-V4 十多个教师）具体机制是否与本文诊断一致未做验证。
- **训练充分性存疑**：300 个 outer step（K=4 下实际 1200 次参数更新）对 3B 模型是否充分收敛不明确；IF 领域在 [100,200] 窗口仍出现下降，训练曲线未完全稳定。
- **消融梯子不对称**：K=1 梯子仅验证 share 和 gap，refresh 只在 K=4 完整配方中验证；缺乏 K=4 下"share+gap 无 refresh"与"单独 refresh"的完整 2×2 消融；gap 的 α 值仅报告 α=1 和 α=−0.5，未对中间值做参数敏感性分析。
- **统计可靠性**：未报告多随机种子和多运行方差；部分指标（如 IFB test mean@1，仅 16.00→24.67）绝对值偏低，可能存在天花板效应。
- **基础模型选择的两难暴露**：1.7B 模型的失败无法完全归因于算法——这揭示了小模型在长链推理任务中的基本能力限制，但也意味着 Open-MOPD 的诊断结论可能高度依赖所选基础模型的容量区间。
- **奖励刷新的适用范围**：论文使用同步管道，奖励刷新只解决"可修复的陈旧性"（即学生相关部分），但 rollout 采样的轨迹仍然来自旧策略，这部分 off-policy 偏差无法消除。
