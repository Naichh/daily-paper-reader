## 摘要
视觉在线策略蒸馏（OPD）通过利用当前学生模型生成的轨迹来改进紧凑型视觉自回归模型的训练。然而，这些在线滚动仍然采用自回归解码逐词生成，给每个在线训练步骤增加了大量成本。投机雅可比解码（SJD）提供了一种替代方案，因为它可以在没有辅助草稿模型的情况下并行处理多个标记，但原始方法是为单序列推理设计的。我们提出了HB-SJD，一种用于视觉OPD的批量SJD滚动后端。HB-SJD允许每个图像根据其自身的解码进度独立推进，而不同序列位置的图像仍在批量模型前向中验证。当图像完成时，HB-SJD在完整执行和紧凑执行之间切换，以降低后续滚动轮次的成本。HB-SJD仅替换了学生滚动后端，保留了教师模型、蒸馏目标和优化过程不变。使用LlamaGen的实验表明，HB-SJD大幅减少了滚动和端到端训练时间，同时保持了蒸馏学生的生成质量。

## Abstract
Visual on-policy distillation (OPD) improves the training of compact visual autoregressive models by learning from trajectories generated by the current student. However, these online rollouts are still produced token by token with autoregressive decoding, which adds substantial cost to every on-policy training step. Speculative Jacobi Decoding (SJD) provides an alternative because it can process multiple tokens in parallel without an auxiliary draft model, but the original method is designed for single-sequence inference. We introduce HB-SJD, a batched SJD rollout backend for visual OPD. HB-SJD allows each image to advance independently according to its own decoding progress, while images at different sequence positions are still verified in batched model forwards. As images finish, HB-SJD switches between Full and Compact execution to reduce the cost of later rollout rounds. HB-SJD only replaces the student rollout backend and leaves the teacher, distillation objective, and optimization procedure unchanged. Experiments with LlamaGen show that HB-SJD substantially reduces rollout and end-to-end training time while preserving the generation quality of the distilled student.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：视觉自回归（AR）模型（如 LlamaGen、VAR）在图像生成上表现出色，但其参数量大、推理成本高。知识蒸馏（KD）可将大模型（教师）能力迁移至紧凑学生模型，但传统蒸馏存在**训练与推理行为不匹配**的问题——学生推理时必须基于自身先前输出进行逐 token 解码，而训练时却依赖真实数据或教师轨迹。
- **核心问题**：视觉在线策略蒸馏（OPD）通过让学生模型在训练时自行生成轨迹来缓解这种不匹配，但代价是**将自回归生成直接引入训练循环**——每次训练更新前都必须在线生成学生轨迹，逐 token 解码使 rollout 成为训练关键路径上的瓶颈，极大增加了每个 on-policy 训练步骤的计算成本。作者的核心问题是：**如何在不改变学习过程的前提下加速学生 rollout？**

### 2. 论文提出的方法论

**核心思想**：将投机雅可比解码（Speculative Jacobi Decoding，SJD）扩展为批量训练场景下的 rollout 引擎，命名为 **HB-SJD（Hybrid Batched Speculative Jacobi Decoding）**，实现并行多 token 生成与验证，同时保持批量 GPU 并行效率。

**关键技术细节**：

- **为何选择 SJD**：SJD 无需辅助草稿模型，通过复用同一学生的雅可比迭代预测作为草稿，避免在训练过程中维持草稿模型与不断更新的学生模型对齐的额外开销。
- **独立批次推进（Independent Batched SJD）**：每个图像维护独立的提交游标和雅可比窗口（W 个草稿 token），按各自解码进度推进；不同序列位置的图像仍在同一个批处理学生前向中验证，避免了 batch-synchronous 执行中快图像等待慢图像的同步开销。
- **批量验证机制**：
  - **贪心验证**（Greedy）：草稿 token 与学生模型 argmax 预测一致时接受。
  - **概率验证**（Probabilistic）：遵循 SJD 的概率接受规则，按 α = min(1, p/q) 接受草稿，拒绝后从校正分布重采样。
- **混合 Full/Compact 执行**：随着图像逐步完成，活跃图像数逐渐减少。Full 执行保持物理批形状但在高活跃度时更高效；Compact 执行只处理活跃图像，在活跃集足够小时更优。HB-SJD 根据硬件校准阈值 γ 动态切换执行模式。
- **历史偏移初始化**：利用视觉 token 的空间局部性，用固定历史偏移 H 处的已提交 token 填充草稿窗口，而非随机初始化。
- **保持训练流程不变**：HB-SJD 仅替换学生 rollout 后端，教师模型、蒸馏目标和优化过程完全不变。

**关键公式**：
- 视觉 AR 模型分解：pθ(x1:T) = ∏Tt=1 pθ(xt | x<t)
- OPD 混合分布：pkmix,θ(x̃1:T) = pdata(x̃1:k) ∏Tt=k+1 pS,θ(x̃t | x̃<t)
- OPD 损失：LOPD = E[ (1/(T−k)) ∑Tt=k+1 DbiKL(pS,θ(·|x̃<t), pT(·|x̃<t)) ]
- 执行模式选择：E(r) = Full（当 A(r) > γ），否则 Compact

### 7. 优点

- **工程实用性强**：直接作为即插即用的 rollout 后端，不改变蒸馏目标和优化流程，易于集成到现有 OPD 方法中。
- **方法设计贴合场景**：针对批量训练的实际工程特性（图像完成时间不同、活跃批缩小、KV-cache 索引开销）设计独立进度与混合执行策略，而非简单套用推理加速方法。
- **去除草稿模型对齐负担**：利用 SJD 无需辅助草稿模型的特点，避免了在 OPD 训练中学生策略变化导致的草稿模型适配问题。
- **验证策略灵活性**：同时支持贪心和概率两种验证策略，后者与未来 SJD 优化兼容。
