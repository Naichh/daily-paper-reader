## 摘要
大语言模型后训练通过强化学习和同策略蒸馏生成自生成轨迹，但一旦策略推进，这些经验往往被视为过时。历史轨迹可以与后续策略保持兼容，同时保留该策略不再能可靠表达的行为。然而，它们也可能包含错误、被放弃的尝试和不应被模仿的冗余动作，这促使我们采用更细粒度的选择性监督。我们提出 ROSS（通过选择性监督从自生成轨迹中重新学习），它将完整历史轨迹保留为上下文，同时仅对选定的模型生成续写计算损失。在领域特定强化学习、多教师同策略蒸馏和智能体强化学习中，ROSS 持续提升上游检查点，并在数学、代码生成、指令遵循和软件工程方面优于基线。在 Qwen3.6-35B-A3B 上，ROSS 将六基准 MOPD 平均分从 58.40% 提升到 62.20%，并将 SWE-bench Verified 从 64.20% 提升到 68.40%。这些结果表明，自生成轨迹训练留下了可复用的行为经验，可通过离线监督微调（SFT）进一步获益，而无需额外的策略轨迹采样。

## Abstract
Large language model post-training generates self-generated rollouts through reinforcement learning and on-policy distillation, yet this experience is often treated as stale once the policy advances. Historical rollouts can remain compatible with a later policy while preserving behaviors that the policy no longer expresses reliably. However, they may also contain mistakes, abandoned attempts, and redundant actions that should not be imitated, motivating finer-grained selective supervision. We introduce ROSS (Relearning from Self-Generated Rollouts through Selective Supervision), which preserves the full historical trajectory as context while applying loss only to selected model-generated continuations. Across domain-specific reinforcement learning, multi-teacher on-policy distillation, and agentic reinforcement learning, ROSS consistently improves upstream checkpoints and outperforms baselines across mathematics, code generation, instruction following, and software engineering. On Qwen3.6-35B-A3B, ROSS improves the six-benchmark MOPD average from 58.40% to 62.20% and SWE-bench Verified from 64.20% to 68.40%. These results show that self-rollout training leaves behind reusable behavioral experience that can yield further gains through offline supervised fine-tuning (SFT), without additional policy rollouts.

## 1. 核心问题与整体含义

- **研究背景**：LLM 后训练（强化学习 RL、同策略蒸馏 OPD）会持续从当前策略采样轨迹并更新模型，这一过程不仅产生一系列 checkpoint，还留下大量自生成经验（成功推理路径、替代策略、自我纠错等）。
- **核心痛点**：策略一旦推进，历史轨迹通常被当作"过时数据"丢弃。但作者指出两个关键观察：
  - **兼容性（Compatibility）**：历史轨迹在当前策略下的 token 级 NLL 与当前策略自身采样接近，且显著低于外部教师轨迹 → 历史行为与当前策略仍高度兼容（Fig. 3a）。
  - **互补性（Complementarity）**：历史上解出的难题在当前策略下 pass@1 仅 37.7%，但 pass@32 达 99.0%，98 题中 74 题成功率 ≤50% → 行为仍"存在"却未被可靠表达（Fig. 3b/3c）。
- **细粒度难题**：即便轨迹整体成功，内部也可能夹杂错误、被放弃的尝试、冗余探索与绕路（Fig. 1b），因此"结果正确"不代表每个中间步骤都值得模仿。
- **整体含义**：论文提出把历史自生成轨迹视为**可复用的行为经验资产**，通过"轨迹级筛选 + token 级选择性监督"的离线 SFT 阶段，在不额外采样策略轨迹的前提下继续提升上游 checkpoint。

## 2. 方法论（ROSS）

### 2.1 核心思想
- 从原始训练run的**最终 checkpoint θ_T** 出发，复用此前各阶段保存的 rollout，先按结果验证器筛掉失败轨迹，再由 LLM reviewer 判定轨迹内哪些片段值得模仿，最后只对这些片段施加 teacher-forcing 损失。
- 关键原则：**mask 只把 token 移出 loss，不把 token 移出序列**，完整原始前缀（含错误、放弃分支、环境反馈）始终作为上下文保留。

### 2.2 形式化与流程（Algorithm 1）
- 记 checkpoints 为 {π_{θ_k}}，rollout 批次为 {D_k}，历史经验池 **H_{<T} = ∪_{k<T} D_k**；从 π_{θ_T} 初始化。
- 轨迹 τ = (z_1,…,z_L)，用 a_t ∈ {0,1} 标记该 token 是否为可被模仿的策略生成 token（prompt、环境观察等外部上下文 a_t = 0）。
- **轨迹级选择**：g(τ) = 1[v(τ) = 1]，v 为结果验证器（答案匹配、单测、执行器、环境成功信号），保留集合 H⁺。
- **轨迹内选择**：LLM reviewer A 审查任务、完整轨迹与验证证据，返回审计状态 q_τ 与有序区间 K_τ = {[b_j, e_j)}，编译为 token mask：
  - m_t(τ) = a_t · 1[ t ∈ ∪_{[b,e)∈K_τ} [b, e) ]
- **训练子集**：H_ROSS = { τ ∈ H⁺ : q_τ = ACCEPT, K_τ ≠ ∅, VALIDATE(τ, m(τ)) = 1 }，VALIDATE 为确定性检查（源一致性、边界唯一性、token 对齐）。
- **目标函数**（masked teacher-forcing）：
  - L_ROSS(θ) = − Σ_τ Σ_t m_t(τ) log π_θ(z_t | z_{<t}) / Σ_τ Σ_t m_t(τ)
- **对照定义**：令 m_t = a_t 即 **ROSS w/o mask**（同一子集、全 token 监督）；**Positive-Rollout SFT** 则对所有验证器通过轨迹的全部可监督 token 施加损失。

### 2.3 两套标注协议
- **单轮 Math/Code：正向 span 提取（positive-span selection）**
  - 第一判官三选一：全响应监督 / 保留有序干净 span / 拒绝；用逐字 start–end anchor 定位，anchor 缺失、重复、歧义或乱序即作废。
  - 第二判官对"实际被选中的文本"独立审计；若发现可分离错误则修订 anchor 并复检；无法仅从原文恢复完整正确解则丢弃。
  - 明确规则：正确答案不能为先前错误背书；冗余但正确的验证不算错误；span 需自包含、含完整最终答案。
- **Agentic 轨迹：语义诊断 + 缺陷定位（defect localization）**
  - 语义判官按 assistant step 分组审查，从四个维度评估每次工具调用：接口契约、操作意图实现、环境前置条件、实际执行结果；API 接受/退出码 0 不等于操作正确。
  - 区分**现存错误（error，可锚定源文本）**与**缺失（omission，无源 token，不可用相邻有效代码代偿）**；后续成功不抵消先前确认的错误，合理的探索性失败不算错。
  - 第二判官做最小源边界定位，返回精确 selector 与受保护邻域；无法可靠定位则标记 unresolved 并整条候选作废。
- **指令遵循**：响应短、推理少，验证器通过即监督全部可监督 token，不做 span 级掩码。
- **掩码编译**：单轮为 A_τ ∩ K_τ，agentic 为 A_τ \ E_τ；不拼接、不重写、不重新分词，只把字符区间投影到已存 tokenizer 的 token 偏移。

  - Positive-Rollout SFT（对全部验证器通过轨迹做全轨迹 SFT）
