## 摘要
迭代式自蒸馏使 LLM 智能体能够从连续部署中学习，为递归自我改进（RSI）提供了一条路径。然而，我们在现有方法上的实验表明，部署性能会随周期出现崩溃，同时使用特权信息（PI）的任务性能也会下降。我们通过优先选择信息量丰富的交互步骤进行蒸馏，并在学生模型成为下一轮教师模型时保留以 PI 为条件的行为，来应对这一崩溃。我们提出 ReSAIL（Retentive and Selective Augmentation for Iterative Self-Distillation），一种面向基于 PI 的迭代式自蒸馏的即插即用增强方法。ReSAIL 选择 PI 对教师模型预测改变最大的交互步骤，并平衡各轨迹上由此产生的蒸馏损失。它还将学生模型的 PI 条件输出分布正则化到冻结教师模型在选中和未选中步骤上的输出分布，以保留 PI 条件行为，用于下一周期的监督。在 ALFWorld 和 TextCraft 上，ReSAIL 在三个周期内跨模型规模持续取得显著提升；当将其加入自蒸馏基线时，最终周期成功率的平均绝对提升为 22.5%。基于敏感性的离线数据选择也提高了 AITZ 上多模态 GUI 智能体的动作预测准确率。这些发现首次证明，更稳健的学习机制能够有效缓解迭代式智能体自蒸馏在部署轨迹中的性能崩溃。

## Abstract
Iterative self-distillation enables LLM agents to learn from successive deployments, offering a path toward recursive self-improvement (RSI). Yet our experiments with existing methods reveal a collapse in deployment performance across cycles, while task performance with privileged information (PI) also declines. We address this collapse by prioritizing informative interaction steps for distillation and preserving PI-conditioned behavior as the student becomes the next teacher. We introduce Retentive and Selective Augmentation for Iterative Self-Distillation (ReSAIL), a plug-in augmentation for iterative PI-based self-distillation. ReSAIL selects interaction steps where PI most strongly changes the teacher's predictions and balances the resulting distillation losses across trajectories. It also regularizes the student's PI-conditioned output distributions toward those of the frozen teacher at selected and unselected steps to preserve PI-conditioned behavior for supervision in the next cycle. On ALFWorld and TextCraft, ReSAIL sustains substantial gains across model scales over three cycles, with an average absolute gain of 22.5% in final-cycle success rates when added to self-distillation baselines. Sensitivity-guided selection of offline data also improves action prediction accuracy for multimodal GUI agents on AITZ. These findings provide the first evidence that a more robust learning mechanism can effectively mitigate performance collapse in iterative agent self-distillation over deployment trajectories.

- **核心问题**：作者用 SDPO 和 OEL 做实验发现，**迭代式自蒸馏并不保证持续改进，反而在连续部署周期中出现性能崩溃**（图 1a）；同时，以 PI 为条件的任务能力也随周期下降（图 1b）。这暴露了两个被忽视的问题：
  - **Q1**：哪些交互步骤应被优先用于蒸馏？作者假设 PI 最能改变教师预测的步骤携带最多可迁移监督信号。
  - **Q2**：当学生成为下一轮教师时会发生什么？基础目标只训练学生的**普通视图**（无 PI），并未显式保留其**特权视图**行为，而更新后的学生正是下一轮提供 PI 条件监督的教师，导致 PI 条件能力被侵蚀。
- **整体含义**：论文首次证明，**通过更稳健的学习机制（选择性蒸馏 + 特权行为保留）可以有效缓解迭代智能体自蒸馏的部署崩溃**，为 RSI 提供更可靠的路径。

## 2. 方法论：核心思想与关键技术细节

### 2.1 整体框架
- ReSAIL 是面向"基于 PI 的迭代自蒸馏"的**即插即用增强模块**，由两部分组成：
  - **TBSD（Trajectory-Balanced Selective Distillation）**：周期内的选择性蒸馏。
  - **PR（Privileged Retention）**：跨周期的特权行为保留。
- 训练设定：周期 r 中，起始策略 πr 与固定轨迹数据集 Dr 配对，**完全离线、不进行额外环境交互**。每条轨迹 τ = ⟨hτ,t, ỹτ,t⟩，PI 为 cτ。策略有两个共享参数的视图：普通视图 π(·|h) 与特权视图 π(·|h, c)。学生 πS 与冻结教师 πT 均从 πr 初始化，更新后的学生成为 πr+1，并在部署时以普通视图行动。

### 2.2 基础自蒸馏
- 在训练响应 zτ,t 的每个前缀上，学生普通视图匹配教师特权视图（token 平均的 student-to-teacher KL）：
  - ℓdist(τ,t) = (1/|z|) Σk DKL( πS(·|h,z<k) ‖ πT(·|h,c,z<k) )
- 对所有交互步骤集合 U 均匀平均得 Lbase。

### 2.3 Trajectory-Balanced Selective Distillation（TBSD）
- **Sensitivity-Guided Selection（SGS）**：定义 **PI 敏感度**为该策略普通视图与特权视图输出分布的 **Jensen–Shannon 散度**（在响应各前缀上平均）：
  - sπ(h,c;z) = (1/|z|) Σk JSD( π(·|h,z<k), π(·|h,c,z<k) )
  - 用**冻结教师**的敏感度对 U 中每步打分，按选择比例 ρ 做 **TopK** 选择，得到选中集合 Cρ。
- **Trajectory Loss Balancing（TLB）**：为避免步骤多的轨迹获得更大总权重，先在每条轨迹内对选中损失取平均，再按整个轨迹批次大小归一化：
  - Lsel = (1/|B|) Σ_{τ:mτ>0} (1/mτ) Σ_{t∈Cρ(τ)} ℓdist(τ,t)
  - 每条有选中步骤的轨迹总系数为 1/|B|，无选中步骤的轨迹贡献为 0。

### 2.4 Privileged Retention（PR）
- 为保留"更新后学生作为下一轮教师"所需的 PI 条件行为，将学生的**特权视图**输出分布正则化到冻结教师的特权视图：
  - ℓret(τ,t) = (1/|z|) Σk DKL( πS(·|h,c,z<k) ‖ πT(·|h,c,z<k) )
- 覆盖 U 中**全部步骤（含未被选中蒸馏的步骤）**，采用与 TLB 相同的轨迹级归约：
  - Lret = (1/|B|) Σ_{τ:|U(τ)|>0} (1/|U(τ)|) Σ_{t∈U(τ)} ℓret(τ,t)

### 2.5 联合目标与优化
- **L = Lsel + λ·Lret**，λ ≥ 0 控制保留强度。
- 每次更新重新计算教师敏感度分数与选中集合，并在反向传播中**固定**这些量（响应、分数、选中索引均不参与微分）。
- 实现细节：使用 **Top-20 + 残差尾部**近似 JSD 与两个 KL；固定 tie 顺序；不做事后轨迹覆盖补全；AdamW，恒定学习率 1e-6，无 warmup。

## 3. 实验设计：数据集 / 场景、Benchmark 与对比方法

- **Benchmark 与场景**：
  - **ALFWorld**：具身家居任务规划，分 **ID** 与 **OOD**，各 128 个 episode，指标为成功率（30 步交互上限）。
  - **TextCraft**：组合式合成任务，官方完整测试集 100 个 episode。
  - **AITZ**：Android GUI 导航，固定监控子集 101 个 episode、843 个非 stop 步骤，指标为步骤级动作准确率（官方 EM 规则）。
- **模型**：
  - 文本任务：**Qwen3-4B**、**Qwen3-8B**（关闭 thinking 模式）。
  - AITZ：**Qwen3-VL-4B-Instruct**。
- **对比基线**：ReAct（不变的初始策略）、RFT、offline GRPO、EPD、offline SDPO、OEL；ReSAIL 分别作为 **SDPO** 与 **OEL** 的插件进行评测；AITZ 上对比 OEL 与 OEL + SGS（仅用于离线数据过滤）。
- **训练协议**：文本任务进行 **3 个周期、每周期 30 次更新**，每周期使用新采集轨迹、从自身上一周期最终 checkpoint 初始化；AITZ 为单周期 100 次更新、每次 16 条源轨迹，OEL+SGS 固定保留全局 top 80% 交互步骤。
- **评估**：每个周期评测最终 checkpoint，报告 3 个解码种子的均值与标准差；保留分析中在固定 128 个 OOD 任务、固定 PI 下做**双视图（有/无 PI）**评测。
